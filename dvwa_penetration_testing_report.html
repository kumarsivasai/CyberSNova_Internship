DVWA Penetration Testing Report

A hands-on vulnerability assessment and penetration testing project against the intentionally vulnerable Damn Vulnerable Web Application (DVWA), performed in an isolated local lab.

Objectives & Scope

Objectives

  • Build and verify an isolated DVWA lab.
  • Identify common web application vulnerabilities.
  • Compare Low, Medium and High security levels.
  • Map findings to OWASP Top 10.
  • Rate risks and recommend remediation.
  • Document evidence professionally.

In scope

  • Local DVWA v2.5 at 127.0.0.1.
  • Kali Linux 2025.1c, Apache, PHP 8.4 and MariaDB.
  • All 14 listed DVWA modules.
  • Low, Medium and High security levels.

Out of scope

  • External or production systems.
  • Denial-of-service testing.
  • Attacks on the host OS outside the lab.
  • Social engineering against real people or websites.

Testing Methodology

A structured, manual-first approach based on the OWASP Web Security Testing Guide (WSTG).

01 · Planning & setup

Define scope, prepare the virtual lab, install and configure DVWA.

02 · Reconnaissance

Review module inputs, parameters and normal behavior.

03 · Identification

Test inputs for weak validation, missing controls and unsafe data handling.

04 · Controlled validation

Confirm weaknesses in the authorized lab and record proof of concept.

05 · Impact analysis

Assess potential impact and assign severity.

06 · Remediation

Identify root causes, recommend fixes and compare the Impossible level.

07 · Reporting

Document findings, evidence, impact and recommendations.

Evidence & Reporting Checklist

Capture

  • Show the module and security level.
  • Include relevant source code.
  • Record the request or payload used.
  • Capture the resulting response.

Label

  • Use figure labels such as Fig 7.1.1.
  • Add a descriptive caption to each screenshot.
  • Record blocked attempts honestly.
  • Ensure every figure reference has a matching image.

Protect

  • Keep evidence beside the related finding.
  • Crop unrelated personal or terminal information.
  • Use lab-only credentials only inside the isolated lab.
  • Take a VM snapshot before testing.

Rules of Engagement & Disclaimer

All testing must remain within the locally hosted DVWA instance in the isolated lab. The target is not to be exposed to the internet. No denial-of-service testing, attacks on external systems, or social engineering against real people are permitted. Take a VM snapshot before testing and restore it if needed.

This page is a web presentation of the supplied README, not a replacement for the full technical report. Detailed per-step evidence and exploit results should be added only where they are documented and verified.
